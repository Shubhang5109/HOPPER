# HOPPER data model

This document describes the shape of the data under `data/`. It is meant to
be read alongside the files themselves — every field below is a real field
in `data/hopper_records.json`.

## Entities: `data/hopper_records.json`

Every record — regardless of whether it represents a host, a pathogen, a
disease, a gene, a strain, a phenotype, or a reference to an external
dataset — shares one common schema:

| Field | Meaning |
|---|---|
| `HOPPER_ID` | Stable identifier, e.g. `HOPPER:DIS:0001`. Prefix encodes entity type: `HOST`, `PATH`, `DIS`, `GENE`, `STRAIN`, `PHENO`, `DATA`. |
| `Entity_Type` | One of `Host`, `Pathogen`, `Disease`, `Gene_Resistance_Factor`, `Strain_Isolate`, `Phenotype`, `Dataset`. |
| `Name` / `Normalized_Name` | Display name and a normalized/scientific form. |
| `Host`, `Pathogen`, `Disease` | Cross-references by name to the relevant biological context. |
| `Pathogen_Type` | Controlled: `Fungus`, `Oomycete`, `Bacterium`, `Virus`. |
| `Strain_or_Isolate`, `Gene_or_Protein`, `Resistance_Factor`, `Phenotype` | Populated where relevant to the entity type. |
| `Environmental_Context`, `Geographic_Region`, `Crop` | Contextual fields. |
| `Data_Type` | Free-text description of what kind of data this record represents (descriptive, not a filter facet — see below). |
| `Source_Database`, `Source_ID`, `Source_URL` | Provenance: which external resource this was integrated from, its original identifier (or `Not available` if this is a resource-level reference rather than a specific record), and a real URL. |
| `Ontology_Term` | Where available, a controlled-vocabulary anchor (e.g. a Plant Ontology or NCBI Taxonomy concept). |
| `Synonyms` | Array of alternate names, used by search. |
| `Evidence_Type` | Free-text description of the kind of evidence (experimental curation, computational prediction, image annotation, etc). |
| `Year` | Publication/reference year where known. |
| `License_or_Access_Status` | e.g. `Open access`. |
| `Provenance` | A human-readable note — always present, never blank. |
| `Last_Checked` | ISO date the source link/status was last verified. |

Unpopulated fields use `null`, `"Unknown"`, or `"Not available"` — never a
fabricated value.

## Relationships: `data/relationships.json`

A flat list of typed edges: `{ type, source, target, note }`, where `source`
and `target` are `HOPPER_ID`s (or `null` for a handful of attribute-style
edges like `ENTITY_HAS_SYNONYM` that carry information in `note` instead of
pointing at a second entity). Edge types in use:

```
HOST_HAS_DISEASE               DISEASE_CAUSED_BY
HOST_HAS_RESISTANCE_FACTOR     RESISTANCE_FACTOR_TARGETS_PATHOGEN
PATHOGEN_HAS_STRAIN            DISEASE_HAS_PHENOTYPE
PATHOGEN_REPRESENTED_IN        ENTITY_LINKED_TO_DATASET
ENTITY_HAS_SYNONYM             ENTITY_ASSOCIATED_WITH_REGION
```

## Sources: `data/sources.json`

One row per external database/resource HOPPER references (the directory
shown on the **Databases** page): name, domain, data type, organism/crop
coverage, HOPPER's integration role, external URL, access status,
geographic scope, a short note, `Last_Checked`, and — where independently
verified — a `Reference_Publication` object (`Title`, `Authors`, `Year`,
`Venue`, `URL`) linking to the paper that describes that resource. About
half of the 28 sources have a verified citation; the rest show "not
verified for this prototype" rather than a guessed one. Record pages for
`Dataset`-type entities look up this field by `Source_Database` name and
display it in the Provenance section alongside the record's own
`Source_URL`.

## Identifier mappings: `data/identifier_mappings.json`

A small curated set of "hub" concepts (e.g. *rice blast*, *cassava mosaic
disease*) each showing the chain of HOPPER records — and the external
databases behind them — that represent the same underlying biology. This is
the data behind the richer cross-reference view on the Explore page, in
addition to the relationship-derived matrix that works for any entity.

## Schema mapping: `data/schema_mapping.json`

The normalization layer: for each canonical HOPPER field (`HOST`,
`PATHOGEN`, `DISEASE`, …) a plain-language description and a list of the
differently-named source fields it's meant to stand in for (`host_species`,
`plant`, `crop_species`, … → `HOST`). This prototype does not run a
mapping *engine* against live external schemas — it documents the mapping
concept and demonstrates it through the normalized data above.

## Regenerating the data

All five files are generated by `scripts/build_data.py` from plain Python
data structures — see [Maintenance](../README.md#adding-a-new-record-or-source)
in the README for how to add a new host, pathogen, disease, gene, dataset,
or source.
